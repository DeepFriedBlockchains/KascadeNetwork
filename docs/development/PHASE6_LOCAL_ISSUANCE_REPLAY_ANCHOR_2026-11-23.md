# Phase 6 local replay issuance anchor

The checkpoint store can compute the expected digest from a complete local consensus replay. A pinned selected-chain guard is required, and every hash and index is checked against the committed database before deriving the root. The supplied configuration binds genesis and cap. An imported checkpoint is verified against the digest produced separately from that checkpoint. The focused RocksDB regression covers equal-total source substitution, rejected and abandoned batches, successful reopen, and replacement after an actual selected-chain reorganization.

The caller still needs to collect trusted claims and releases from local consensus validation. The existing pruning proof authenticates the selected child and its shielded state root. It carries no independently validated issuance commitment, so a pruned node cannot use this full-prefix replay interface to authenticate remote issuance by itself. To activate production integration, bind a consensus-validated issuance digest to verified selected-chain evidence, then carry the typed anchor and #51 record into guarded promotion with the ready revision in the same authority batch. This regression uses a batch probe, and the production readiness integration remains unproven. Production issuance and the proposed 29B cap remain inactive.
