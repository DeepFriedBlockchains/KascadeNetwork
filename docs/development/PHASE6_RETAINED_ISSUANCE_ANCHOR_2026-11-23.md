# Phase 6 locally retained issuance replay anchor

A node that previously verified a complete local replay can retain the independently derived anchor and checkpoint together in the existing RocksDB authority batch. Recovery reads both from a single database snapshot and verifies them against its configured network and cap and the still-selected pruning point. A missing anchor, altered digest, wrong context, or stale fork fails closed. The focused regression exercises the real selected index pruning method, RocksDB reopen, missing and altered evidence and reorganization after pruning.

A fresh pruned receiver still has no trusted local replay. Header transaction roots authenticate supplied bodies, the accepted-ID root commits accepted transaction IDs, and the UTXO commitment covers the UTXO set. The existing selected-child coinbase path authenticates the shielded state root. None independently commits to canonical cumulative issuance, including deferred developer releases. To bootstrap remote state, consensus must validate such a commitment and bind it to the verified selected child or an independently authenticated checkpoint before the pruning authority can consume it. The retained pair does not publish readiness. A real guarded publication regression must prove that the authenticated issuance pair and readiness commit together through interruption, reopen and reorg. Production issuance remains disabled.
