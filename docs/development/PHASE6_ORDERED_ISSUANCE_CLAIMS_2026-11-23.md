# Phase 6 ordered issuance claim derivation

The candidate consensus-core derivation checks each settlement anchor against an independently verified selected path supplied by the caller. The source hash is unique across the input. Canonical order is selected-chain index followed by reward-source hash. The existing transaction hasher and Merkle implementation commit the source, anchor, index and atomic amounts. Checked addition caps minted issuance, reconciles paid and deferred totals at each selected settlement block, and rejects overflow. The checkpoint verifier still requires a digest from a separate trust path. A peer's recomputed digest is insufficient evidence.

The virtual processor persists mergeset acceptance and the selected-chain index. AcceptanceData records source block hashes and accepted transaction IDs, while coinbase calculation consumes reward subsidy, fee and ephemeral settlement context. Those interfaces do not currently supply an authoritative persisted attribution of newly minted and deferred amounts per reward source or an authenticated issuance digest. The whole-history derivation is for bounded inputs. Before guarded promotion, add an incremental, reorg-aware claim view from real settlement, derive the independently authenticated digest from verified consensus evidence, and stage the verified claim/settlement rows in the same deferred batch as the ready revision. The integration test must exercise actual mixed subsidy, recycled fees and deferred spending, then reject sibling ancestry and altered claims and prove identical state after restart and interrupted writes.

This draft changes no reward activation, wire formats, or production pruning behavior. Legacy settlement evidence remains on #46 and the test-only guarded-batch evidence remains on #47.
