# Phase 6 issuance checkpoint reference tests

This model exercises the approved #26 integer schedule inside a bounded test-only ledger. Its commitment binds the network, chain point, ordered source identities, paid amount and deferred amount. Restore compares against a separately supplied expected commitment. Gross outputs less recycled fees and plus the change in deferred entitlement must equal authorized issuance. The tests reject duplicate source identities, a genesis claim, settled entitlement paid twice, changed order, altered paid/deferred split, over-cap issuance, and overflow.

The retained claim list is a fixture oracle capped at 64 entries. Production must prove uniqueness using accepted DAG state across pruning and reorg. The model exercises snapshot binding in memory and does not authenticate a network proof, persist an ordinal to RocksDB, alter the coinbase wire format or activate any schedule. Before production, verify the actual eligible-source list and expected checkpoint commitment against the accepted pruning proof and child body, and atomically bind readiness and both transparent and shielded settlement state. The 29B maximum and separate 21B/8B budget model are inherited from #26.
