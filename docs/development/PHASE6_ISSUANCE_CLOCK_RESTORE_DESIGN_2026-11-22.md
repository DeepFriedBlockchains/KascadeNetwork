# Phase 6 issuance clock and authenticated restore proposal

November 22, 2026. Source reviewed at `15f99ca97799b414e57fb20b8f53f1d85feb1f6c` on draft [#25](https://github.com/DeepFriedBlockchains/KascadeNetwork/pull/25). The 35-year target is nominal at five unique rewarded units per second. The primary and tail lengths are 1,577,880,000 and 3,944,700,000 units. This proposal requires owner approval before consensus integration.

## What the source clocks measure

| Clock | Consequence for the proposed issuance rule |
| --- | --- |
| Source block DAA score, as used by the current subsidy payload | Sibling blocks can share a score and later contribute independent eligible rewards. Treating that score as an exclusive slot can assign the same scheduled amount more than once. Using the accepting block’s score for each output has the same multiplicity problem in a larger mergeset. |
| Selected-parent DAA delta with ordered per-edge offsets | The current DAA recurrence adds the number of mergeset sources outside the non-DAA set. Under separate proof obligations, a validated parent score minus an approved launch offset could compress the issuance cursor. This requires equality with the actual eligible source count on every path, including genesis, pruning proof, activation and the terminal regime. It couples the supply rule to DAA semantics and does not assign individual positions by itself. |
| Blue score, selected-chain height, offered blocks, or wall time | Blue score advances by blue blocks and omits subsidy-eligible reds. Chain height counts a multi-source accepting edge once. Offered blocks include excluded sources. Timestamps do not authenticate one unique authorized source. Each choice changes either issuance allocation or throughput semantics. |
| Branch-specific ordinal over unique eligible sources | Counts each consensus-ordered, subsidy-eligible source attached to the selected-parent history. Handles multiple eligible sources in one edge and explicit exclusions without modifying the DAA. Requires versioned authenticated state or a proven derivation when history is pruned. |

DAA is useful as a measurement and a count cross-check. The recurrence is `daa(current) = daa(selected_parent) + mergeset_size - non_daa_count`. The sampled window treats genesis specially when building the window. Use the agreed candidate reward eligibility explicitly in both validator and template builder even where the DAA delta agrees. [Competing-tip test #30](https://github.com/DeepFriedBlockchains/KascadeNetwork/pull/30) exercises equal-score sources and [red accounting test #31](https://github.com/DeepFriedBlockchains/KascadeNetwork/pull/31) exercises subsidy-eligible and fee-only reds. ## Recommended initial candidate

Start from a separately identified, explicitly authorized fresh Simnet genesis. Store a versioned after-transition cursor on each accepted block context, starting at zero. Enumerate the selected parent and other sources in `GhostdagData::consensus_ordered_mergeset`, with blue-work ordering and its existing hash tie-break. Exclude genesis and any source excluded from subsidy by the candidate policy. Subsidy-eligible blue and red sources each take one position. Non-DAA sources take none. Preserve existing fees, including the fee-only path for non-DAA red sources, outside the issuance total.

For parent cursor `s`, assign the first qualified source ordinal `s` and assign successive qualified sources increasing ordinals. Set the cursor to `min(s + eligible_count, 5_522_580_000)` using checked arithmetic. Compute each source subsidy from the difference of the integer cumulative-prefix schedule at consecutive ordinals. Derive the transition’s authorized new subsidy from the same prefix difference and independently check that per-source amounts sum to it across primary/tail and tail/zero boundaries. After the endpoint, every subsidy is zero and fee handling continues. Track any post-terminal throughput separately from the capped issuance cursor. Split each eligible source’s subsidy before aggregating red rewards, and test that miner, KRN, developer and authorized fallback allocations conserve the source amount. Refunds and fees recycled from already issued value do not consume a slot. Deferred allocation counts once at authorization and later settlement must not authorize it again.

The intended uniqueness proof uses the full mergeset as the newly attached DAG past on a selected-parent edge. Those past increments must be disjoint along the selected history. Review redundant-parent canonicalization and pruning-summary boundaries before relying on this proof, then test it against a small append-only reference set. Avoid a global ever-seen map that makes competing history count against the winner. The same source can have different provisional ordinals on different forks. Reorgs must select the winning parent context and recompute the canonical claims. Repeat insertion and alternate arrival order must produce identical committed state.

Current body validation checks a miner-carried, DAA-derived subsidy field and virtual processing copies that field into merge rewards. An active profile must change both sources of truth together. Define a versioned payload rule and compute amounts from the accepting branch context during both template construction and validation. Preserve legacy consensus parsing and behavior at inactive profiles. In the transparent path a selected parent's coinbase enters the UTXO view in the child, while shielded minting uses the current block's verified coinbase. Treat the cursor as **authorization for a consensus transition**, then verify that both issuance paths settle each authorization once at their respective transition boundary. Never recover the cursor from the count or value of outputs, circulating UTXOs, or shielded-pool balance. ### Genesis and time semantics

Current genesis construction produces no coinbase outputs. The inherited payload still contains 100,000,000 base units in its subsidy field, so the zero-output observation alone cannot establish that no descendant can claim it. The fresh candidate should use a zero issuance genesis state, make genesis explicitly ineligible, and test the first accepted claims through both builder and validator. A preallocation or adoption over previously issued state would require a separate owner-approved transition that carries cumulative historical obligations and subtracts them from approved budgets. A cursor reset over live issuance would invalidate the 29B cap proof. [Genesis constructor](https://github.com/DeepFriedBlockchains/KascadeNetwork/blob/15f99ca97799b414e57fb20b8f53f1d85feb1f6c/consensus/core/src/config/genesis.rs#L25) · [Inherited payload](https://github.com/DeepFriedBlockchains/KascadeNetwork/blob/15f99ca97799b414e57fb20b8f53f1d85feb1f6c/consensus/core/src/config/genesis.rs#L104)

Calendrical duration is an estimate. At an observed mean of 4, 5, or 6 eligible unique claims per second, the 5,522,580,000-unit horizon lasts about 43.75, 35.00, or 29.17 years respectively. Actual throughput may differ from 5-BPS block creation because excluded sources, delayed merges, competing branches and skipped periods change eligible claims. Instrument raw rate, unique authorized rate, settlement lag, and eligible blue/red shares separately.

## Authenticating the cursor after pruning

The current snapshot contains shielded metadata and nullifier rows. The current authenticated check rehashes the selected child's header, confirms the point is its selected parent, verifies the body Merkle root and reads the selected-parent shielded root from its coinbase. Separate checks verify imported pruning UTXOs against the pruning header commitment and recheck proof, shielded binding, and other requirements when granting promotion. These checks carry neither a separate issuance cursor nor the commitment to its value. The existing shielded totals describe the pool and cannot recover lifetime mixed-pool authorized issuance. [Snapshot type](https://github.com/DeepFriedBlockchains/KascadeNetwork/blob/15f99ca97799b414e57fb20b8f53f1d85feb1f6c/consensus/core/src/api/mod.rs#L172) · [Child authentication](https://github.com/DeepFriedBlockchains/KascadeNetwork/blob/15f99ca97799b414e57fb20b8f53f1d85feb1f6c/consensus/src/pipeline/virtual_processor/import_shielded_readiness.rs#L82) · [UTXO binding](https://github.com/DeepFriedBlockchains/KascadeNetwork/blob/15f99ca97799b414e57fb20b8f53f1d85feb1f6c/consensus/src/pipeline/virtual_processor/import_readiness.rs#L93) · [Promotion recheck](https://github.com/DeepFriedBlockchains/KascadeNetwork/blob/15f99ca97799b414e57fb20b8f53f1d85feb1f6c/consensus/src/pipeline/virtual_processor/processor.rs#L2587)

Extend the activated consensus commitment with a versioned, domain-separated commitment for the selected parent's issuance state. One possible carrier is the verified child coinbase payload with its Merkle-authenticated body, using a discriminator and canonical bounded encodings for network/genesis, schedule/activation identity, parent hash and cursor. Bind the parent point from the child context to avoid a hash self-reference. Validation must rebuild the commitment from the same parent state and reject mismatched rules, counters or cash flows. A hash binds an authenticated checkpoint value. It does not prove correct lifetime arithmetic by itself. The trust model must be the approved pruning-proof/qualified selected-chain model or replay from a trusted checkpoint, documented explicitly.

Export the issuance checkpoint against the same pinned pruning and selected views as the other state. Authenticate the proof-selected child's header and body, selected-parent relationship and position on the approved ancestry. Reject missing or mismatched active-profile issuance metadata. Load and verify the cursor and totals before enabling consensus mutations, then replay the selected descendants exactly once from that checkpoint. Check the reconstructed cursor against the committed selected tip, and require either a matching authenticated tip-child commitment or sufficient verified replay. Preserve the existing readiness marker checks, stale generation rejection and database lock ordering. Runtime application and durable import promotion must atomically commit issuance state and affected ledger/readiness data. Reopen must read persisted committed state and fail closed if it is inconsistent. No downgrade to zero or to raw DAA as a missing-row default. Existing [commit path](https://github.com/DeepFriedBlockchains/KascadeNetwork/blob/15f99ca97799b414e57fb20b8f53f1d85feb1f6c/consensus/src/pipeline/virtual_processor/processor.rs#L1255) already batches reward-relevant accepted-state data with UTXO-valid status and provides an implementation site to audit.

## Validation required before activation

1. Prove mergeset disjointness over selected-parent ancestry under redundant parents, competing tips, pruning summaries and unqualified heads. Test duplicate arrival, equal source DAA, DAA jumps, non-DAA blue and red, eligible red, many-source transitions and stable ordering after reopen.
2. Run independent integer prefix vectors at genesis, each phase boundary, terminal zero and checked overflow, plus mixed mergesets straddling both boundaries. Compare production builder and validator payloads, miner/KRN/developer/fallback sums, deferred commitments, and actual transparent and shielded settled value. Revalidate inactive network compatibility.
3. Compare state after rewind, alternate arrival/replay, partition/rejoin and RocksDB reopen. Compare issuance cursor, authorized supply, output records, fee totals and commitments against an independently replayed node.
4. At a genuinely pruned checkpoint, import into a fresh node with no relevant historic rows, replay retained descendants, and compare the next reward and resulting ledger with a full replay. Cover proof and commitment mismatch, missing or out-of-range state, wrong schedule/network/point, stale or incorrect child, interruption at each storage boundary, repeated import, reorg around pruning and rejection of an activated peer that cannot provide required data.
5. Run the scoped Simnet regressions and full eight-job matrix with default-off safeguards. Advance throughput interpretation only after sustained measurement of eligible unique units. Keep public pool interoperability and production activation as separate acceptance decisions.
